# 블랙아웃 인수인계

이 문서 하나로 다음 사람(또는 다음 AI)이 이어받을 수 있게 쓴다.
코드를 읽기 전에 이걸 먼저 읽으면 「왜 이렇게 돼 있나」를 두 번 묻지 않아도 된다.

- **배포 주소**: `joeltool.com/blackout/` — `main` 에 합쳐져 GitHub Pages 로 배포 중.
- **저장소 경로**: `blackout/` · 브랜치 `claude/realtime-turn-based-dark-battle-xc922d`
- **빌드 도구 없음.** `index.html` 을 브라우저로 열면 그대로 돈다. ES5, 외부 의존성 0.
- **그림의 정답**: `assets/concept/concept-01.jpg`. 결국 이 느낌이 나와야 한다.
- **지금 버전: v0.7 «컨셉아트 수준»** (규칙은 v0.5 그대로, 넷코드 버전 `bo0.5-glow1`).

## 1. 어떤 게임인가

불 꺼진 방에서 **보이는 건 내가 바라보는 쪽뿐인 채로** 야광 페인트건을 주고받는
턴제 대전. 실시간으로 붙어서 두지만(WebRTC/WebSocket) 게임은 턴제다.
까맣던 방이 페인트로 조금씩 드러난다 — 검은 크레파스를 긁어내는 스크래치 아트.

### 규칙 (v0.5 — 설계자의 여섯 가지 반영, 2026-09-13)

1. 방은 **8×8**, 사무실·침실·거실 중 하나(씨앗이 정한다). **가구는 미리 보이지 않는다.**
   시작 구역만 공개 — 0번(청록)은 위 2줄, 1번(분홍)은 아래 2줄.
2. 한 턴에 **행동 2번**. 이동 2 / 이동 1 + 사격 1 / 사격 2.
3. **시야각** — 마지막으로 움직인 방향(`face`)으로 앞 1·2·3칸 부채꼴(좌우 1·1·2칸,
   `CONE=[1,1,2]`)이 보인다. 그 안의 가구와 **상대**가 보인다. 가구 뒤는 안 보인다(LOS,
   브레젠험). 옆·뒤는 안 보인다. 자기 칸은 늘 안다. 처음엔 서로를 향해 본다.
4. **부딪힘** — 모르는 칸으로 가다 가구면: 행동력 1 소모, 그쪽을 보게 되고(face), 그 칸을
   알게 된다. 자리는 그대로. 아는 가구로 가는 건 규칙 위반(화면이 막는다).
5. 사격은 **어느 칸이든**(가구 포함) 겨눌 수 있다. 사거리 없음. 맞으면 체력 1, **5번이면 패배.**
   **사격은 쏜 사람의 위치를 알려주지 않는다.** 소리와 얼룩이 전부다.
6. **페인트는 야광이다.** 맞은 칸이든 빗나간 칸이든 얼룩이 **판이 끝날 때까지** 남고, 그 칸이
   무엇이었는지 둘 다 알게 된다(`known`). 얼룩은 그 칸의 그림을 얼룩 모양으로 뚫어 보여 준다.
7. **맞으면 야광이 묻어 윤곽이 보인다**(`foe.why === 'glow'`). 움직이면 꺼진다 —
   **한 칸만** 움직이면 발을 뗀 칸에 **발자국**(야광, 영구), **두 칸**이면 남지 않는다.
   안 움직이면 계속 보인다. 바닥의 **얼룩을 밟아도** 똑같이 묻는다(다음 턴부터).
8. 캐릭터끼리는 막지 않는다. 같은 칸에 겹쳐도 «본 것»으로 치지 않는다 — 접촉은 정보가 아니다.
9. **전등 버튼** — 가운데 띠(3~6줄) 바닥 칸 하나, 매 판 랜덤. 밟으면 불이 켜지고 **방 전체
   (가구·상대)가 드러난다.** 행동 하나 뒤에 꺼지지만 본 가구는 기억한다. 불은 켠 사람도 비춘다.
10. **인기척** — 바로 옆 한 칸까지 가까워지면 양쪽 다 낌새를 챈다. 방향은 모른다.
11. 140턴이 지나면 체력이 많은 쪽이 이긴다. 같으면 무승부.
12. 대전 중 **상대가 사라지면 30초**를 기다렸다가 남은 쪽의 기권승.

### 핵심 고리

> 바라보는 쪽만 보인다 → 찾으려면 **움직여야** 한다 → 모르는 칸은 **부딪히고** 얼룩은 **밟는다**
> → 밟으면 **윤곽이 보인다** → 맞으면 **한 발 더**(윤곽) → 도망치면 **발자국** → 방이 점점 밝아진다

### 왜 판이 빨리 끝나나 (봇 1,500판)

| | v0.5 (8×8·시야각) | v0.4 (10×10·전등만) |
|---|---|---|
| 격추로 끝난 판 | **96.5%** | 86.1% |
| 무승부 | 1.7% | 5.1% |
| 선공 승률 | 46.7% | 52.4% |
| 평균 턴수 | **14.8** | 47 |
| 명중률 | 74.9% | 11.7% |
| 첫 명중 턴 중앙값 | 5 | — |
| 전등 · 페인트밟기 · 발자국 (판당) | 0.34 · 0.23 · 0.16 | 2.75 · 1.70 · 0.10 |

시야각 폭을 어떻게 바꿔도(1,1 / 0,1,1 / 0,0,1) 15~23턴이다. 「보이면 쏘고, 맞히면 윤곽으로
한 발 더」가 판을 끝낸다. 사람은 봇보다 느리게 찾으니 실전은 이보다 길다. 재려면
`CONE=0,1,1 node blackout/tests/balance.js 1500`.

### 지켜야 할 경계 — 이게 이 코드의 전부다

| 파일 | 아는 것 | **절대 모르는 것** |
|---|---|---|
| `rooms.js` | 방 모양·가구·막힌 칸 (정답지) | 플레이어 위치. 누가 뭘 봤는지 |
| `core.js` | 규칙 | DOM · 네트워크 · 시간 · `Math.random` |
| `net.js` | 메시지 나르기 | 게임 규칙 |
| `match.js` | 턴 순서 · 동기화 | 어떻게 그리는지 |
| `ui.js` `bot.js` | 그리기 / 추리 | 상태 원본 — `Core.view()` 가 준 것만 본다 |
| `art.js` | 어떤 그림 파일이 있나 | 규칙 · 상태. **보이는 것만** 바꾼다 |

**`core.js` 는 순수 함수다.** 무작위는 서버가 준 씨앗(`create(seed)`)으로만.
양쪽 브라우저가 같은 입력에서 반드시 같은 상태를 내야 하고, 매 턴 해시로 대조한다.

**정보 누출은 구조로 막는다.** `Core.view(st, 나)` 가 주는 것:

- `tiles[64]` — **아는 칸만** 채워진다(`{kind, name, walk, material, ox, oy, w, h}`), 모르면 `null`.
  가구 정답지(`room.objects`)는 화면에 **절대 안 간다**(테스트가 `objects` 문자열을 검색한다).
- `seen` — 지금 시야각 칸들. `me.face` — 바라보는 방향.
- `foe` — 상대 좌표는 **세 경우에만**: `why: 'lit'`(전등) / `'seen'`(내 시야) / `'glow'`(야광 윤곽).
  아니면 `null`. 같은 칸에 겹친 상대는 «본 것»이 아니다.
- `foeSeen` — 내가 마지막으로 본 자리(맞힘·전등·**시야 목격** 중 최근). `meSeen` — 내가
  공개적으로 노출된 기록(맞음·전등)만. **상대가 나를 시야로 봤다는 건 내가 알 수 없다**
  (`st.spot` 은 본 쪽에게만 나간다).
- `paint`/`marks` — 영구. `age` 만 는다. `legalDirs` — 격자 안이고 «아는 가구»가 아닌 방향.
- 상대 턴의 `moves`/`stepFrom` 은 안 준다. 인기척은 참/거짓 한 비트.

상태(`st`)에 v0.5 에서 들어간 것: `ps[i].face`, `ps[i].known[64]`, `spot[2]`. 전부 해시에 들어간다.
`look(st, side)` 이 행동 뒤마다 시야를 `known` 에 더하고, `noteSpots` 가 목격을 적는다.

### 화면(ui.js/rooms.css)의 층 — v0.6 «장난감 디오라마»

설계자의 기준은 **멧챠 카멜레온**(2026, 알록달록하고 어수선한 방을 장난감처럼 그린
숨바꼭질 게임)의 미감 + 우리 컨셉아트(위에서 본 어두운 방, 스탠드 불빛, 청록/분홍 페인트).

칸(`.cell`)마다: `.art`(그림, z1: 내장 SVG 또는 파일, `--art` 로 칸 단위 슬라이스) → 판 전체
SVG 세 장(z2: `.fogsvg` 안개 64칸을 **한 장으로 흐려** 가장자리가 부드럽고, `.beam` 시야의
따뜻한 빛 웅덩이 + 내 주위 은은한 빛, `.gridsvg` 옅은 점선 격자) → `.fog`(z3: 이제 투명한
«테두리 층» — 갈 수 있는 칸·고른 칸·인기척 링) → `.splat > .paint`(z4, `mask:var(--sv)` 로
그림을 얼룩 모양으로 뚫고 페인트 색을 덧입힌다 = 스크래치 아트) → `.mark`/`.lamp`(z5) →
사람 `::after`(z6, 살짝 숨쉬듯 bob) → `.dir`(z7) → `.ghost`(z8) → `.reaction`/`.burst`(z9) →
고른 칸 `::before`(z10) → 비네트 `::before`(z11). 안개 두께는 ui.js 가 rect opacity 로:
모름 1 / 기억 .72 / 지금 봄 .05 / 불 켜짐 0. 격자 자체는 두꺼운 청회색 벽(`border`)으로 감싼다.
상대는 `.foe-lit`/`.foe-seen`(실루엣)/`.foe-glow`(**윤곽만**, 점선). 마루는 3칸짜리 널빤지 한
장을 칸마다 1/3 씩(`--px`), 줄마다 어긋나게, 톤은 `--fb` 로 살짝씩 다르게 깐다.
체력은 페인트 방울 5개. 제목·큰 글자는 Google Fonts «Jua»(못 받으면 시스템 글꼴).

**타격은 네 겹**으로 알린다(설계자: 「맞았는지 맞혔는지 모르겠다」): 격자 한가운데 큰 글자
(`#toast`) · 흔들림/번쩍임(`.board.shake`, `#hurt`, 토큰 `.jolt`, `.burst-*`) · 소리(`hurt` 는
무겁게, `hit` 은 밝게, 둘 다 «철퍽» 잡음) · 진동(`navigator.vibrate`). 체력 구슬은 `.pip.lost` 로 튄다.

## 3. 규칙을 만질 때

### 눈금은 한 군데 — `js/core.js` 맨 위 `var C`

```
W,H = 8   HP = 5   AP = 2   MAX_TURNS = 140   SPAWN_BAND = 2
CONE = [1,1,2]   LOS = 1   LAMP_ACTIONS = 1   RANGE = 0(무제한)   SENSE = 1
```
페인트·발자국 기한은 **없다**(영구). 예전 `PAINT_TURNS`/`MARK_TURNS` 는 사라졌다.

### **반드시 먼저 재고 옮긴다**

```
node blackout/tests/balance.js 2000
CONE=0,1,1 LOS=0 SENSE=0 node blackout/tests/balance.js 2000     # 눈금: CONE LOS RANGE SENSE LAMP MAXT
```

### 실제로 있었던 일 — 같은 실수를 반복하지 않기 위해

1. **처음 규칙 그대로는 한 판도 안 끝났다** (10×10, 격추 0%). 전등 버튼이 해결했다.
2. **총성(쏘면 쏜 자리가 뜬다)은 넣었다가 뺐다.** 설계에 없던 규칙. 다시 넣지 말 것(테스트가 못 박는다).
3. **충돌 규칙도 뺐다.** 겹침은 정보가 아니다 — v0.5 의 시야각도 같은 칸은 «안 본 것»으로 친다.
4. **인기척은 넓힐수록 나빠진다.** 1 이 설계자 확정값.
5. **10×10 은 너무 컸다**(실서버 2판째, 「찾기가 어렵다」). 8×8 + 시야각으로.
6. **튜토리얼 안내판이 격자 위를 덮어 그 밑 칸을 못 눌렀다** — 8×8 로 칸이 커지자 생겼다.
   안내판은 클릭을 통과시키고 버튼만 눌린다(`.tut{pointer-events:none}`).

## 3½. 화면 조작과 로비

- **고르고 → 확정.** 이동이든 사격이든 방향키·터치로 칸을 짚고 [확정]. 같은 칸을 두 번
  짚는 것도 확정이다. 키보드: 방향키/WASD · Enter · Space(모드) · Esc.
  이동 모드에서 모르는 칸은 고를 수 있다(부딪힐 수 있다). 아는 가구는 못 고른다.
- **전장 크기**는 `style.css` 의 빼는 값 세 벌(372 / ≤720 은 328 / ≤600 은 276), 가로 폰은
  그리드, PC 는 820px. 조작부를 바꾸면 `tests/layout.js` 로 다시 잰다(7기종).
- **로비는 방을 절대 숨기지 않는다.** `?diag=1` 로 서버 응답 원문. 인원수 필드는 `members`.
- **튜토리얼** 8단계: 소개 → 이동(시야) → 사격(야광) → 전등 → 불빛 아래 사격 → 윤곽·발자국 →
  추적 → 끝. 봇은 가르치는 모드. 판은 고정 씨앗(20260913), 시계 없음.

## 4. 넷코드

- 서버(Cloudflare DO `arena-room`)는 **씨앗과 시작만** 정한다. 에그워와 공용, 버전 악수로 분리.
- 행동 하나는 **그 즉시** `{t:'a', n, k, a}`, 턴이 끝나면 `{t:'t', n, a, h}`. 받는 쪽은 `a` 를
  순서대로 적용해 두고 `t` 에서 뒷부분만 마저 적용한 뒤 해시 대조. `a` 없이 `t` 만 와도 같다.
- 재접속 복구 = **씨앗 + 턴 기록 재생.** 록스텝이 아니다.
- 실제 방 서버 CORS 는 `https://joeltool.com` 만. localhost 는 대역(`tests/roomserver.js`).
- 서버가 거절하면 로비 상태줄에 사유: 4009 버전 불일치 · 4004 없는 방 · 4008 이름 충돌.
- 친구 초대는 `?room=코드` 링크 하나.

**알려진 한계 — 치트를 막지 못한다.** 양쪽이 전체 상태(상대 좌표·가구 정답지)를 들고 있다.

## 6. 그림 — 어떻게 채우나

**명세는 `assets/README.md`.** 파일을 넣고 `node blackout/tests/assets-manifest.js`.

**v0.7 — 그림은 컨셉아트에서 오렸다.** 설계자가 「컨셉아트 수준으로」라고 했고 그림 생성
도구는 안 쓰기로 했으니, 컨셉 두 장에 이미 그려진 가구·마루·얼룩을 `tests/concept-crops.py`
로 잘라 칸 규격에 맞췄다(Pillow). 조각 둘레는 알파를 부드럽게 해서 같은 그림에서 온 마루와
녹아든다. 마루는 맨 바닥 76×126 조각을 거울 타일로 깔고(이음매 없음) 방마다 조명(스탠드·달빛)과
가장자리 그늘을 구웠다(JPG, 800×800). 얼룩 마스크는 그림 속 페인트의 채도로 뽑았다.
파일 이름은 **`<kind>-<w>x<h>.png`** — 같은 kind 라도 크기별로 다른 그림이다(art.js 가 크기별을
먼저 찾고 없으면 `<kind>.png`). 없는 파일은 **내장 SVG**(`js/svgart.js`)로 보인다.

⚠ `art.js` 의 `BASE` 는 **절대 주소**다. CSS 변수(--art/--floor/--splat)에 넣은 `url()` 을 크롬은
«변수를 쓴 스타일시트(css/rooms.css)» 기준으로 풀어서, 상대 주소면 `css/assets/…` 로 가 404 가
났다(마루와 가구가 전부 검게 나온 원인이었다).

v0.5 부터 그림은 **칸 단위로 잘라** 쓴다(`art.js` `slice`) — 가구는 시야에 든 칸만 보이고
얼룩은 그 칸의 조각을 뚫어 보여 주기 때문이다. 그래서 「책상 3칸 그림 한 장」을 넣으면
게임이 알아서 세 조각으로 쓴다. 바닥 그림도 한 장을 64조각으로.

**원칙 — 가구 자리는 그림이 아니라 `rooms.js` 데이터가 정한다.** 바닥 그림에 가구를 그리지 말 것.
시점은 정확히 위에서 아래. 전체 2MB. 채도 높은 색은 청록·분홍(야광)만. **얼룩은 흰색으로**
(마스크로 쓴다, 색은 CSS 가 입힌다).
