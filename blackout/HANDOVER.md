# 블랙아웃 인수인계

이 문서 하나로 다음 사람(또는 다음 AI)이 이어받을 수 있게 쓴다.
코드를 읽기 전에 이걸 먼저 읽으면 「왜 이렇게 돼 있나」를 두 번 묻지 않아도 된다.

- **배포 주소**: `joeltool.com/blackout/`
- **저장소 경로**: `blackout/`
- **전체 용량**: 224KB (이미지·오디오 자산 0개)
- **빌드 도구 없음.** `index.html` 을 브라우저로 열면 그대로 돈다.

## 1. 어떤 게임인가

불 꺼진 10×10 방에서 **서로 절대 보이지 않는 채로** 페인트건을 주고받는 턴제 대전.
실시간으로 붙어서 두지만(WebRTC/WebSocket), 게임은 턴제다.

### 규칙

1. 10×10. 서로의 모습은 보이지 않는다. 시작 구역만 공개 — 0번은 위 3줄, 1번은 아래 3줄.
2. 한 턴에 **행동 2번**. 이동 2 / 이동 1 + 사격 1 / 사격 2 자유 조합.
3. 사격은 **어느 칸이든** 겨눌 수 있다. 사거리 제한 없음.
   맞으면 체력 1, **5번 맞으면 패배.**
4. **사격은 쏜 사람의 위치를 알려주지 않는다.** 상대가 아는 건 「어딘가에서 한 발
   나갔고 이 칸에 떨어졌다」뿐이다.
5. 맞은 칸이든 빗나간 칸이든 **페인트가 5턴 동안** 바닥에 남는다. 얼룩은 양쪽 다 본다.
6. 맞으면 신발에 페인트가 묻는다. 그 상태로
   - **한 칸만** 움직이면 → **발을 뗀 칸에 발자국**이 남는다(3턴 보임)
   - **두 칸** 움직이면 → 흔적이 안 남는다. 대신 그 턴엔 못 쏜다.
   - 안 움직이면 → 페인트가 그대로 남아 다음 턴으로 넘어간다.
7. 바닥의 **페인트를 밟아도** 똑같이 묻는다. 효과는 **다음 턴부터**.
8. 상대 칸으로 들어가면 **부딪힌다.** 제자리로 돌아오지만 **둘 다 위치가 드러난다.**
9. **전등 버튼** — 방 가운데 띠에 버튼 하나, 매 판 랜덤 위치.
   밟으면 불이 켜지고 서로가 보인다. **행동 하나**가 지나면 꺼진다.
10. **인기척** — 바로 옆 한 칸까지 가까워지면 양쪽 다 낌새를 챈다. 방향은 모른다.
11. 140턴이 지나면 체력이 많은 쪽이 이긴다. 같으면 무승부.

### 핵심 고리

> 모르겠으면 **버튼을 하러 간다** → 가려면 **움직여야** 한다 → 움직이면 **페인트를
> 밟는다** → 밟으면 **발자국**이 남는다 → 발자국 때문에 **잡힌다**

버튼이 이 고리의 시동이다. 버튼이 없으면 아무도 움직일 이유가 없고,
움직이지 않으면 5·6·7번 규칙이 통째로 죽은 코드가 된다.

### 전등 버튼의 긴장

켜는 건 공짜가 아니다.

- 불은 **켠 사람도 비춘다.** 상대도 내 위치를 본다.
- **마지막 행동으로 켜면** 남은 불빛 한 행동이 **상대 차례로 넘어간다.**
  내 위치만 공짜로 보여 주고 끝난다.
- 그래서 「첫 행동으로 켜고 둘째 행동으로 쏜다」가 정석이다.
- 버튼 위에 그대로 서 있으면 다시 못 켠다. 한 칸 물러났다 다시 밟아야 한다 —
  그 사이 상대는 내가 버튼 근처에 있다는 걸 안다.

## 2. 코드 구조

```
blackout/
├── index.html          화면 골격 (메뉴·규칙·로비·방·대전·결과)
├── README.md           설계 배경 · 에그워에서 가져온 것과 안 가져온 것
├── HANDOVER.md         이 문서
├── css/style.css       204줄 — 어둠 테마 · DOM 격자
├── js/
│   ├── core.js   416줄  규칙 엔진
│   ├── net.js    564줄  방 접속(WebSocket) + P2P 직결(WebRTC)
│   ├── match.js  326줄  턴 진행 · 해시 대조 · 재접속 복구
│   ├── bot.js    246줄  연습 상대
│   ├── ui.js     302줄  화면 그리기 · 조작
│   ├── main.js   264줄  화면 전환 · 로비 · 연결 배선
│   └── sfx.js     52줄  WebAudio 소리
└── tests/              검증 6종
```

### 지켜야 할 경계 — **이게 이 코드의 전부다**

| 파일 | 아는 것 | **절대 모르는 것** |
|---|---|---|
| `core.js` | 규칙뿐 | DOM · 네트워크 · 시간 · `Math.random` |
| `net.js` | 메시지 나르기 | 게임 규칙 |
| `match.js` | 턴 순서 · 동기화 | 어떻게 그리는지 |
| `ui.js` | 그리기 · 입력 | 상태 원본 (`Core.view()` 가 준 것만 본다) |
| `bot.js` | 추리 | 상대 좌표 (`Core.view()` 만 본다 — 속이지 않는다) |

**`core.js` 는 순수 함수 덩어리다.** DOM 을 만지지 않고, 타이머를 걸지 않고,
`Math.random` 을 부르지 않는다. 이유는 하나다 — **양쪽 브라우저가 같은 입력에서
반드시 같은 상태를 내야 한다.** 여기에 난수나 시간이 한 줄 들어가는 순간
두 사람이 서로 다른 판을 보면서 싸우게 된다.

무작위가 필요하면 **서버가 준 씨앗**(`create(seed)`)으로만 만든다.

### 정보 누출 방지가 구조로 박혀 있다

`ui.js` 와 `bot.js` 는 상태 객체(`st`)를 **직접 받지 않는다.**
`Core.view(st, 나)` 가 내준 것만 본다. 그 객체에는

- 내 좌표 · 내 체력 · 상대 체력 (공개)
- 얼룩 · 발자국 · 전등 버튼 자리 (공개)
- 인기척 (참/거짓 한 비트)
- `foe` — **불이 켜졌을 때만** 값이 차고, 꺼져 있으면 `null`

숨김 정보 게임에서 제일 흔한 사고가 「화면이 무심코 상대를 그려 버리는 것」인데,
받는 물건에 애초에 그 열쇠가 없으면 그 사고가 구조적으로 안 난다.
**이 경계를 허물지 말 것.** 테스트가 지키고 있다(`core.test.js` 의 「화면이 보는 것」).

## 3. 규칙을 만질 때

### 눈금은 한 군데에만 있다

`js/core.js` 맨 위 `var C = { ... }`. 지금 값:

```
W,H = 10          HP = 5            AP = 2
PAINT_TURNS = 5   MARK_TURNS = 3    MAX_TURNS = 140
SPAWN_BAND = 3    LAMP_ACTIONS = 1  RANGE = 0(무제한)  SENSE = 1
```

### **반드시 먼저 재고 옮긴다**

```
node blackout/tests/balance.js 2000
```

봇끼리 N판 두고 격추율·명중률·무승부·발자국 발생 횟수를 센다.
눈금은 환경변수로 돌린다: `RANGE` `SENSE` `LAMP` `MAXT`

```
SENSE=2 node blackout/tests/balance.js 2000      # 인기척 넓히면?
LAMP=0 node blackout/tests/balance.js 2000       # 전등 빼면?
```

**이 게임은 눈으로 봐서는 규칙이 맞는지 알 수가 없다.** 어둠 속이라 화면에
아무것도 안 보이기 때문이다. 숫자로만 확인된다.

### 실제로 있었던 일 — 같은 실수를 반복하지 않기 위해

1. **처음 규칙 그대로는 한 판도 안 끝났다.**
   격추 0% · 무승부 76% · **이동 0회 · 발자국 0회.**
   어디든 쏠 수 있으면 움직일 이유가 없어서 둘 다 제자리에 붙박였고,
   그러니 페인트를 밟을 일이 없어 5·6·7번 규칙이 한 번도 발동하지 않았다.
   → 해결은 **전등 버튼**이었다. 단서를 「새어 나오는 정보」가 아니라
   「가서 얻어 오는 것」으로 만들자 고리가 돌기 시작했다.

2. **사거리 제한은 도움이 안 됐다.** 2~6 을 다 돌려 봐도 격추율이 오히려 떨어졌다
   (둘이 서로를 아예 못 만난다). 원래 규칙인 무제한이 낫다.

3. **총성 규칙은 넣었다가 뺐다.** 숫자는 잘 나왔지만(격추 92%) 설계에 없던 규칙이었다.
   어둠 속에서 쏘는 사람의 위치가 보일 이유가 없다.

4. **인기척은 넓힐수록 나빠진다.** 반경 1 → 격추 99.8%, 반경 2 → 58.7%, 반경 3 → 29.3%.
   넓으면 「어중간한 단서」가 자주 떠서 13칸짜리 복권을 긁느라 행동력을 쓰고
   정작 버튼을 하러 안 간다.

### 현재 실측 (봇 3,000판)

| | |
|---|---|
| 격추로 끝난 판 | **99.5%** |
| 무승부 | 0.4% |
| 선공 승률 | 48.9% (공정) |
| 평균 턴수 | 35턴 |
| 명중률 | 21.7% |
| 판당 피해 | 8.17 / 10 |
| 전등 · 페인트밟기 · 발자국 · 충돌 | 3.07 · 1.85 · 0.21 · 0.60회 |

## 4. 넷코드

### 어떻게 도는가

```
방 서버(Cloudflare Durable Object, arena-room)
  ├─ 방 만들기 / 목록 (HTTP)
  ├─ 시그널링 (WebSocket) ─→ WebRTC 직결 협상
  └─ 직결 실패 시 릴레이 (WebSocket)
```

- 서버는 **씨앗과 시작 시점만** 정한다. 클라이언트가 정하면 둘이 다른 판을 연다.
- 턴 하나 = 메시지 하나. `{t:'t', n:턴번호, a:[행동들], h:상태해시}`
- 받는 쪽은 **같은 문**(`Core.applyTurn`)으로 적용하고 **해시를 대조한다.**
  어긋나면 조용히 넘어가지 않고 **멈추고 크게 알린다.**
- 재접속 복구는 **씨앗 + 턴 기록 재생**. 끊겼다 붙으면 밀린 턴을 달라고 해서 따라잡는다.

### 록스텝이 아니다 — 일부러

에그워는 실시간이라 록스텝이었고, 「입력 지연을 몇 프레임으로 잡을까」가 판을
좌우했다(중앙값이냐 p95냐로 여러 번 뒤집혔고, 한 번은 조작이 1초 늦어졌다).
이 게임은 턴제라 그 문제가 **아예 생기지 않는다.** 늦게 도착해도 순서만 맞으면
결과가 같다. 지연 산식이 없고, 재접속 복구는 「기록을 다시 재생」 한 줄로 끝난다.

### 건드리기 전에 알아야 할 것

`net.js` 의 주석은 전부 **실제로 사람이 신고해서 알게 된 것**들이다. 지우지 말 것.

- **백그라운드 전환은 퇴장이 아니다.** `pagehide` 에서 방을 나가면 폰 화면이
  꺼지는 순간 자기 손으로 방을 나간다.
- **끊김에는 두 종류가 있다** — 다시 붙는 중(`drop`)과 정말 끝(`close`).
  구분 안 하면 깜빡임 한 번이 판을 끝낸다.
- **소켓 신원 가드** (`self.ws !== ws`) — 재접속 때 옛 좀비 소켓의 `onclose` 가
  늦게 도착해 새 연결 상태를 덮어쓴다.
- **TURN 자격증명을 클라이언트에 박지 말 것.** 서버 `/ice` 가 단기 발급한다.
- 방 서버는 에그워와 **공용**이다. 버전 악수(`BO.VERSION`)가 달라서 방이 섞이지 않는다.
  버전 문자열을 에그워와 같게 만들면 안 된다.

### 알려진 한계 — 정직하게

**치트를 막지 못한다.** 양쪽이 전체 상태를 들고 있어 개발자도구로 상대 위치가 보인다.
진짜로 막으려면 방 서버가 심판이 되어야 하는데 그 소스는 이 저장소에 없다.
대안(각자 제 좌표만 들고 피격 판정은 맞은 쪽이 답하기)은 「거짓말」이라는 다른
치트가 열릴 뿐이고, 비동기 왕복이 생겨 재접속 복구가 크게 어려워진다.
**v1 은 「아는 사람끼리 하는 판」을 전제로 결정론 + 해시 대조를 택했다.**

## 5. 검증

```
# 의존성 없음
node blackout/tests/core.test.js      # 규칙 99개
node blackout/tests/balance.js 2000   # 봇 대전 밸런스

# playwright 필요
npm i playwright
python3 -m http.server 8765           # 저장소 루트에서
node blackout/tests/roomserver.js     # 방 서버 대역 (:8767)

node blackout/tests/layout.js         # 6기종에서 화면 안 넘치는지
node blackout/tests/pvp.js            # 브라우저 둘을 붙여 한 판
node blackout/tests/safety.js         # 어긋남 감지·복구 · 재접속 따라잡기
```

`roomserver.js` 는 **실제 방 서버가 아니다.** 규약만 같게 흉내 낸 대역이다.
`localStorage['blackout.rtbase']` 로 갈아끼운다.

`safety.js` 에서 배운 것: **소켓만 끊으면 대전이 안 끊긴다.** P2P 직결이 살아 있어서
턴이 그대로 온다. 실전에서는 장점이지만, 재접속 경로를 재려면 두 경로를 다 끊어야 한다.

## 6. 디자인 작업 인수인계

**지금 이미지·오디오 자산이 0개다.** 전부 CSS와 이모지로 그렸다.
가볍지만(224KB) 밋밋하다. 여기가 다음 사람이 채울 자리다.

### 작업 규칙

- **빌드 도구 없음.** 파일을 넣고 CSS/HTML에서 상대경로로 참조하면 끝.
- **외부 의존성 금지.** CDN·폰트 호스트·npm 패키지 전부 쓰지 않는다.
  (아티팩트 미리보기가 외부 요청을 CSP로 막기도 한다.)
- **ES5 로 쓴다.** 화살표 함수·`let`/`const`·템플릿 문자열 쓰지 말 것.
- **용량 예산: 전부 합쳐 2MB 를 넘기지 말 것.**
  에그워는 보스 PNG 하나가 5MB, BGM 한 곡이 6.7MB였고 그게 첫 로딩을 죽였다.
  블랙아웃의 가벼움 자체가 장점이다.
- 자산은 `blackout/assets/` 에 넣는다(지금은 없는 폴더, 만들면 된다).
- 넣고 나서 **반드시** `node blackout/tests/layout.js` 를 돌려 6기종에서
  화면이 안 넘치는지 확인할 것.

### 색 토큰 — 여기서만 바꾼다

`css/style.css` 맨 위:

```css
:root{
  --bg:#07090d;    /* 바탕 — 거의 검정 */
  --panel:#0e141d; /* 패널 */
  --line:#1d2836;  /* 테두리 */
  --dim:#5b6b80;   /* 흐린 글자 */
  --text:#dbe6f3;  /* 본문 */
  --me:#3de1d0;    /* 나 — 청록 */
  --foe:#ff4d8d;   /* 상대 — 자홍 */
  --hot:#ffcc4d;   /* 전등·경보 — 노랑 */
  --tile:#0b1119; --tile2:#0d141e;  /* 바닥 두 색(체크무늬) */
}
```

**어둠이 컨셉이다.** 밝게 만들고 싶은 충동을 참을 것. 화면의 90%가 거의 검정이어야
얼룩 하나·발자국 하나가 정보로 읽힌다.

### 화면 크기 — 손대면 같이 고쳐야 하는 것

격자 크기는 **화면 높이에서 조작부 높이를 뺀 값**으로 정해진다:

```css
.board{width:min(100%, calc(100dvh - 430px))}
@media (max-height:660px){ .board{width:min(100%, calc(100dvh - 370px))} }
@media (max-height:560px){ .board{width:min(100%, calc(100dvh - 240px))} }
```

빼는 값(430/370/240)은 추측이 아니라 실측이다. **조작부에 줄을 더하거나 빼면 이
숫자도 같이 고쳐야 한다.** 안 고치면 작은 폰에서 버튼이 화면 밖으로 밀린다.
고친 뒤 `node blackout/tests/layout.js` 로 확인.

(퍼센트 높이 `height:100%` 로 물려받는 방법을 먼저 썼다가 격자가 24px로 접혔다.
`body` 가 `min-height` 라서 물려줄 확정된 높이가 없었기 때문이다.)

### 하지 말 것

- **캔버스로 바꾸지 말 것.** 에그워가 전체화면 캔버스라 기종마다 레터박스 계산이
  어긋났고 결국 「가로로 돌려주세요」 안내판까지 세워야 했다.
  DOM 격자는 세로 화면에서 그냥 맞는다.
- **가로 화면 강제하지 말 것.** 세로로 돌아간다.
- **자산을 크게 만들지 말 것.** (위 예산 참조)
- **`core.js` 를 건드리지 말 것.** 디자인 작업으로 규칙 엔진을 열 일은 없다.
