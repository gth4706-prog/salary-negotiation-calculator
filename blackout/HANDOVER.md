# 블랙아웃 인수인계

이 문서 하나로 다음 사람(또는 다음 AI)이 이어받을 수 있게 쓴다.
코드를 읽기 전에 이걸 먼저 읽으면 「왜 이렇게 돼 있나」를 두 번 묻지 않아도 된다.
(예전의 `INDOOR-HANDOVER.md` 는 이 문서에 합쳤다. 문서는 **이것 하나**다.)

- **배포 주소**: `joeltool.com/blackout/` — `main` 에 합쳐져 GitHub Pages 로 배포 중.
- **저장소 경로**: `blackout/` · 브랜치 `claude/realtime-turn-based-dark-battle-xc922d`
- **빌드 도구 없음.** `index.html` 을 브라우저로 열면 그대로 돈다. ES5, 외부 의존성 0.
- **그림의 정답**: `assets/concept/concept-01.jpg`. 결국 이 느낌이 나와야 한다.

## 1. 어떤 게임인가

불 꺼진 **사무실 또는 침실**에서 **서로 절대 보이지 않는 채로** 물총(페인트건)을 주고받는
턴제 대전. 실시간으로 붙어서 두지만(WebRTC/WebSocket) 게임은 턴제다.

### 규칙

1. 방은 판마다 **사무실(L자, 오른쪽 아래 3×3 없음)** 또는 **침실(10×8)**. 씨앗이 정한다.
   책상·의자·침대·수납장·서류대는 **막힌 칸**, 러그는 밟을 수 있다. 방 구조는 공개 정보.
   시작 구역만 공개 — 0번은 위 3줄, 1번은 아래 3줄(그중 바닥 칸).
2. 한 턴에 **행동 2번**. 이동 2 / 이동 1 + 사격 1 / 사격 2 자유 조합.
3. 사격은 **방 안 어느 칸이든**(가구 칸 포함) 겨눌 수 있다. 사거리 없음. 중간 가구에 막히지 않는다.
   맞으면 체력 1, **5번 맞으면 패배.**
4. **사격은 쏜 사람의 위치를 알려주지 않는다.** 상대가 아는 건 「어딘가에서 한 발 나갔고
   이 칸에 떨어졌다」뿐. 가구를 맞히면 재질대로 반응(종이 흩날림·천 스며듦·나무 흘러내림)하지만
   **연출일 뿐 정보가 아니다.**
5. 맞은 칸이든 빗나간 칸이든 **페인트가 5턴** 남는다. 얼룩은 양쪽 다 본다.
6. 맞으면 신발에 페인트가 묻는다. 그 상태로
   - **한 칸만** 움직이면 → **발을 뗀 칸에 발자국**(3턴 보임)
   - **두 칸** 움직이면 → 흔적 없음. 대신 그 턴엔 못 쏜다.
   - 안 움직이면 → 페인트가 그대로 다음 턴으로.
7. 바닥의 **페인트를 밟아도** 똑같이 묻는다. 효과는 **다음 턴부터**.
8. 캐릭터끼리는 **서로를 막지 않는다.** 같은 칸에 겹칠 수 있고, 접촉으로 위치가 드러나지 않는다.
   (v0.1 의 「부딪히면 둘 다 드러남」은 뺐다 — 설계에 없던 규칙이었고, 이동이 막히는 것
   자체가 정보가 된다.)
9. **전등 버튼** — 방 가운데 띠의 바닥 칸 하나, 매 판 랜덤. 밟으면 불이 켜지고 서로가
   보인다. **행동 하나**가 지나면 꺼진다.
10. **인기척** — 바로 옆 한 칸까지 가까워지면 양쪽 다 낌새를 챈다. 방향은 모른다.
11. 140턴이 지나면 체력이 많은 쪽이 이긴다. 같으면 무승부.
12. 대전 중 **상대가 사라지면 30초**를 기다린다(폰 화면이 꺼진 것일 수 있다). 그 안에
    안 돌아오면 남은 쪽의 **기권승**. 「사라졌다」는 서버가 1명이라 하고 **직결 핑에도
    답이 없는** 상태다 — 서버 소켓만 끊기고 직결로 턴이 오가면 세지 않는다.

### 핵심 고리

> 모르겠으면 **버튼을 하러 간다** → 가려면 **움직여야** 한다 → 가구를 돌아가며
> **페인트를 밟는다** → 밟으면 **발자국**이 남는다 → 발자국 때문에 **잡힌다**

버튼이 이 고리의 시동이다. 버튼이 없으면 아무도 움직일 이유가 없고,
움직이지 않으면 5·6·7번 규칙이 통째로 죽은 코드가 된다(실측으로 확인했다).

### 전등 버튼의 긴장

- 불은 **켠 사람도 비춘다.**
- **마지막 행동으로 켜면** 남은 불빛 한 행동이 **상대 차례로 넘어간다.** 그래서
  「첫 행동으로 켜고 둘째 행동으로 쏜다」가 정석.
- 버튼 위에 서 있으면 다시 못 켠다. 한 칸 물러났다 다시 밟아야 한다.

## 2. 코드 구조

```
blackout/
├── index.html          화면 골격
├── README.md           설계 배경 · 에그워에서 가져온 것과 안 가져온 것
├── HANDOVER.md         이 문서
├── css/style.css       기본 어둠 테마 · DOM 격자
├── css/rooms.css       실내 맵 · CSS 시험 가구 · 그림이 있을 때의 모양(has-*)
├── assets/             그림·소리. README.md 가 명세. 지금은 아이 토큰·발자국만 있다.
├── js/
│   ├── rooms.js   공개 방 데이터 · 막힌 칸 · 경로 거리 (씨앗으로 맵 선택)
│   ├── core.js    규칙 엔진 — DOM·네트워크·시간·Math.random 을 모른다
│   ├── net.js     방 접속(WebSocket) + P2P 직결(WebRTC). 버전 bo0.2-rooms1
│   ├── match.js   턴 진행 · 해시 대조 · 재접속 복구
│   ├── bot.js     연습 상대 — Core.view() 만 본다(속이지 않는다)
│   ├── art.js     assets/ 에 그림이 있으면 찾아서 끼운다. 없으면 CSS 로 논다
│   ├── ui.js      그리기 · 입력 — Core.view() 만 본다
│   ├── main.js    화면 전환 · 로비 · 연결 배선
│   └── sfx.js     WebAudio 소리(파일 없음)
└── tests/          검증 8종 (tests/README.md)
```

### 지켜야 할 경계 — 이게 이 코드의 전부다

| 파일 | 아는 것 | **절대 모르는 것** |
|---|---|---|
| `rooms.js` | 방 모양·가구·막힌 칸 (전부 공개) | 플레이어 위치 |
| `core.js` | 규칙 | DOM · 네트워크 · 시간 · `Math.random` |
| `net.js` | 메시지 나르기 | 게임 규칙 |
| `match.js` | 턴 순서 · 동기화 | 어떻게 그리는지 |
| `ui.js` `bot.js` | 그리기 / 추리 | 상태 원본 — `Core.view()` 가 준 것만 본다 |
| `art.js` | 어떤 그림 파일이 있나 | 규칙 · 상태. **보이는 것만** 바꾼다 |

**`core.js` 는 순수 함수다.** 무작위는 서버가 준 씨앗(`create(seed)`)으로만.
양쪽 브라우저가 같은 입력에서 반드시 같은 상태를 내야 하고, 매 턴 해시로 대조한다.

**정보 누출은 구조로 막는다.** `Core.view(st, 나)` 에는 상대 좌표가 **불이 켜졌을 때만**
`foe` 로 들어오고, 꺼져 있으면 `null` 이다. 상대 턴의 `moves`/`stepFrom` 도 안 준다.
가구 반응·이동은 상대에게 아무 신호도 주지 않는다. 테스트가 지킨다.

## 3. 규칙을 만질 때

### 눈금은 한 군데 — `js/core.js` 맨 위 `var C`

```
W,H = 10   HP = 5   AP = 2   PAINT_TURNS = 5   MARK_TURNS = 3   MAX_TURNS = 140
SPAWN_BAND = 3   LAMP_ACTIONS = 1   RANGE = 0(무제한)   SENSE = 1
```

### **반드시 먼저 재고 옮긴다**

```
node blackout/tests/balance.js 2000
SENSE=0 node blackout/tests/balance.js 2000     # 눈금: RANGE SENSE LAMP MAXT
```

이 게임은 눈으로 봐서는 규칙이 맞는지 알 수 없다. 어둠 속이라 화면에 아무것도 없다.

### 실제로 있었던 일 — 같은 실수를 반복하지 않기 위해

1. **처음 규칙 그대로는 한 판도 안 끝났다** (격추 0% · 무승부 76% · 이동 0회 · 발자국 0회).
   → 전등 버튼이 해결했다. 단서를 «새어 나오는 정보»가 아니라 «가서 얻어 오는 것»으로.
2. **사거리 제한은 역효과.** 2~6 전부 격추율이 오히려 떨어졌다.
3. **총성(쏘면 쏜 자리가 뜬다)은 넣었다가 뺐다.** 숫자는 좋았지만 설계에 없던 규칙.
4. **충돌 규칙도 뺐다.** 설계에 없던 규칙이고 이동이 막히는 것 자체가 정보다.
5. **인기척은 넓힐수록 나빠진다.** 반경 2·3 은 어중간한 단서로 행동력을 낭비하게 만든다.
6. **계측기 버그**: 예전 `balance.js` 는 «0번 플레이어 승률»을 선공 승률로 표시했다.
   Codex 가 잡아 `seed & 1` 기준으로 고쳤다. 그 전 문서의 「선공 48.9%」는 잘못된 값.

### 현재 실측 (실내 맵, 1,500판)

| | 인기척 1 (현재) | 인기척 0 |
|---|---|---|
| 격추로 끝난 판 | 86.1% | **100%** |
| 무승부 | 5.1% | 0% |
| 선공 승률 | 52.4% | 51.3% |
| 평균 턴수 | 47 | 41 |
| 명중률 | 11.7% | 18.7% |
| 전등 · 페인트밟기 · 발자국 (판당) | 2.75 · 1.70 · 0.10 | 4.51 · 3.40 · 0.19 |

숫자만 보면 인기척 0 이 낫다. **그래도 1 이다** — 설계자가 "인기척은 좋다"고 확정했고,
«바로 옆에 있다»는 긴장은 숫자에 안 잡힌다. 바꾸는 건 한 글자.

## 4. 넷코드

- 서버(Cloudflare DO `arena-room`)는 **씨앗과 시작만** 정한다. 방 만들기·시그널링·릴레이.
- 턴 하나 = 메시지 하나 `{t:'t', n, a:[행동], h:해시}`. 받는 쪽은 같은 문(`Core.applyTurn`)으로
  적용하고 **해시를 대조.** 어긋나면 멈추고 크게 알린다(`safety.js` 로 실제 발동 확인).
- 재접속 복구 = **씨앗 + 턴 기록 재생.** 록스텝이 아니라서 지연 산식이 없다.
- 실제 방 서버 CORS 는 `https://joeltool.com` 만 허용. localhost 에서는 대역(`tests/roomserver.js`)으로만.
- 방 목록의 인원수 필드는 **`members`** 다(에그워 로비와 대조). 서버가 거절하면 로비
  상태줄에 사유가 뜬다: 4009 버전 불일치 · 4004 없는 방 · 4008 같은 이름 충돌.
- 친구 초대는 `?room=코드` 링크 하나로 끝난다. 방 화면의 [초대 링크 복사].
- `net.js` 주석은 전부 사람이 신고해서 알게 된 것. 백그라운드 전환은 퇴장이 아니다 /
  `drop` 과 `close` 구분 / 소켓 신원 가드 / TURN 자격증명은 서버 발급 / 버전 악수로 에그워와 분리.

**알려진 한계 — 치트를 막지 못한다.** 양쪽이 전체 상태를 들고 있다. 해시 대조는 보안이 아니다.
공개 대전으로 가려면 서버가 심판이 되어 각자에게 허용된 view 만 보내야 한다. 서버 소스는
이 저장소에 없다(`03-webtool-adsense/workers/arena-room/worker.js` 로만 언급됨).

## 6. 그림 — 어떻게 채우나

**명세는 `assets/README.md`.** 파일 이름·크기·투명 여부·내용이 표로 있다.
파일을 넣고 `node blackout/tests/assets-manifest.js` 를 돌리면 `js/art.js` 가 목록을
읽어 쓴다. 목록이 없으면 파일을 하나하나 더듬는데(접속마다 404 가 쌓인다) 그래도 돈다.
없는 파일은 CSS 시험 자산으로 보인다.

지금 있는 것: `sprites/kid-top.png`(아이 토큰) · `footprint-me/foe.png`(발자국) —
컨셉아트에서 잘라냈다. 나머지(바닥 2·가구 10·얼룩 4·전등 2)는 아직 CSS.

**원칙 하나만 기억할 것 — 가구 자리는 그림이 아니라 `rooms.js` 데이터가 정한다.**
방 바닥 그림에 가구를 그리면 안 된다. 가구는 칸 수에 맞는 조각으로 따로 만들어
격자 좌표에 얹는다. 컨셉 그림을 그대로 배경으로 깔면 그림 속 책상과 게임의 막힌 칸이
어긋나서 바로 혼란이 온다(그래서 그렇게 안 했다).

시점은 **정확히 위에서 아래.** 전체 2MB 예산. 색은 청록·분홍만 채도 높게.
넣은 뒤 `node blackout/tests/layout.js`.

캔버스로 바꾸지 말 것(에그워 레터박스 사고) · 가로 강제 금지 · `core.js` 열 일 없음.

## 7. 다음에 할 일

1. **그림 채우기** — `assets/README.md` 순서대로. 얼룩 4장이 제일 효과가 크다.
2. **실제 도메인에서 사람 둘이 확인** — 방 만들기·초대 링크·재대결·두 기기 재접속.
   지금까지의 검증은 전부 로컬 대역 서버 기준이다. 실제 서버가 거절하면 로비 상태줄의
   문구가 답이다.
3. **아이템** (회복 · 세로3 · 가로3 · 2×2 · 수류탄). `core.js` `_shoot()` 이 1칸만 칠한다 —
   모양을 인자로. `st.items` 를 상태에 넣고 **해시에도** 넣을 것. 밸런스·정보 노출 검사 별도.
4. 사람이 두면 발자국이 더 자주 날 것이다(봇은 「묻으면 두 칸 도망」을 정확히 둔다). 실사용 뒤 재측정.
5. 공개 대전 전에 서버 심판.
