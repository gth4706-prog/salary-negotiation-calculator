# 블랙아웃 실내 맵 인수인계 · bo0.2-rooms1

2026-09-13. 이 문서가 기존 HANDOVER.md의 v0.1 규칙·수치보다 우선한다.
지정 브랜치 `claude/realtime-turn-based-dark-battle-xc922d`의 게임을 이어받았다.

## 이번 구현

- 불 꺼진 사무실(L자)과 침실(직사각형). 서버가 전달한 seed로 양쪽이 같은 맵을 선택한다.
- 현재 좌표 저장 공간은 최대 10×10. 사무실은 모서리 3×3칸을 제외하며 침실은 10×8칸이다. 임의 크기의 맵 편집기는 아직 없다.
- 공개된 방 외곽·가구 데이터와 이동 가능 판정을 분리했다. 책상·의자·침대·수납장·서류대는 막히고 러그는 걸을 수 있다. 모든 바닥이 연결되며 시작 구역·전등은 바닥에서만 정한다.
- 방 밖은 사격할 수 없다. 가구는 사격 가능하다. 종이 흩어짐·천 흡수·단단한 재질의 튐은 표적에서만 실행하는 임시 CSS 효과다. 통로, 피해 범위, 가구 위치는 변하지 않는다.
- 가구를 맞혀도 상대를 추리할 추가 정보가 없다. 사격에는 발사 지점이나 탄도가 없으며 중간 가구를 통과해 선택한 칸에 도달한다. 시야선 차단·총알 경로 추적은 이번 규칙이 아니다.
- 인기척 기본값을 0으로 바꾸고 캐릭터 충돌을 제거했다. 서로 같은 바닥 칸을 점유할 수 있다. 이동 실패로 상대를 찾는 것도 막기 위한 판단이다. 제 발밑 사격은 여전히 금지되어 있으므로 겹쳤다면 이동 후 겨냥해야 한다.
- 직접 명중과 전등에 의한 공개는 원래 규칙으로 유지한다. 자동 이동 추리는 발자국으로만 한다.
- 2 AP, 5 HP, 페인트 5턴, 발자국 3턴, 턴 제한 20초, 최대 140턴을 유지했다.
- 발자국 의미는 기존 인수인계 그대로다: 턴 시작에 묻어 있었고 정확히 한 칸 이동했을 때 **출발 칸**에 방향 없는 흔적. 두 칸 이동하면 흔적 없음. 새로 밟은 페인트는 다음 턴부터 적용. 처음 대화의 ‘첫 걸음마다 바로 찍히는 흔적’과 다를 수 있으므로 다음 밸런스 작업에서 명시적으로 결정할 것.

## 코드 경계

`js/rooms.js`: 방 데이터·공개 지형 조회·경로 거리. seed만으로 맵 선택, 매 판 복사본.
`core.js`: 방 구조를 포함한 상태 생성·판정·해시. `Core.view()`에 복사된 공개 room과 legalDirs를 전달한다. 상대 턴의 `stepFrom`과 `moves`는 화면·봇에 전달하지 않는다.
`bot.js`: 공개 이동 가능 칸과 경로 거리로 가구를 돌아간다. 상대 원본 좌표를 읽지 않는다.
`ui.js` / `css/rooms.css`: DOM 위에 가구 표시. 공개 hit/miss 사건만 재질 반응을 트리거한다. 이동에 반응하는 가구 애니메이션은 금지.
`match.js`: 승리 사격이 `over`를 설정한 뒤에도 마지막 턴을 상대에게 정확히 한 번 전송하도록 수정했다.
`net.js`: `bo0.2-rooms1` 버전으로 v0.1·에그워와 분리. 원래 재접속·WebRTC·WebSocket 경로는 유지했다.

출시용 그림/힉스필드 영상은 아직 포함하지 않았다. 현재 가구·캐릭터·페인트는 작은 CSS 시험 자산이다. 앱은 ES5 스크립트, DOM, 상대 경로, 외부 런타임 의존성 없이 동작한다. 테스트 도구는 별도다.

## 확인한 배포 상태

읽기 전용 확인일: 2026-09-13.

- `CNAME`: `joeltool.com`.
- GitHub Pages API: legacy 방식, `main` 브랜치의 `/`를 배포, cname 동일.
- `https://joeltool.com/blackout/`: HTTP 404. 게임이 별도 브랜치에만 있고 main에는 없는 상태였다.
- `https://arena-room.gth3941.workers.dev/rooms`: HTTP 200.
- 실제 방 서버 CORS는 `https://joeltool.com`만 허용한다. localhost에서 실제 서버로 접속하는 브라우저 테스트는 방 생성 전 CORS로 진행하지 못했다. 서버 응답이 있다고 온라인 대전 전체를 검증한 것으로 쓰지 말 것.
- 저장소에 실제 Worker/Durable Object 소스나 wrangler 설정은 없다. `eggwar/js/netroom.js` 주석에 `03-webtool-adsense/workers/arena-room/worker.js` 경로만 남아 있다. 이 이름의 같은 소유자 GitHub 저장소는 조회되지 않았다.
- 로컬 GitHub CLI 인증은 사용 가능했다. 기존 Pages·DNS·Cloudflare 설정은 변경하지 않았다.

## 검증

`node blackout/tests/core.test.js`: 100개 통과.
`node blackout/tests/rooms.test.js`: 1,000개 seed의 두 맵 연결성·출발지·버튼 위치·조회 격리, 재질 반응/이동 비공개, 30개 봇 대전의 기록 재생 해시 일치.
`node blackout/tests/match.test.js`: 승리 사격 양쪽 종료·단일 전송.
`node blackout/tests/layout.js`: 320×568, 360×640, 390×844, 412×915, 820×1180, 900×500에서 넘침 없음.
`node blackout/tests/pvp.js`: 로컬 방 서버 대역으로 브라우저 둘, 14턴, 체력/턴 일치, 어긋남 없음.
`node blackout/tests/safety.js`: 강제 어긋남 감지·기록 복구·연결 끊김 후 따라잡기 통과. 실제 WAN/TURN 검증은 아님.
별도 브라우저 검사: 사무실 서류·침실 침대에 클릭 사격, AP 소비·페인트 생성·상대 위치 비공개 확인.

2,000판 재측정: 격추 100%, 평균 41.4턴, 명중률 18.6%, 선공 승률 51.0%, 발자국 0.21회/판, 전등 4.60회/판. 봇 선택에는 난수가 있어 실행마다 수치가 달라진다. 예전 통계 코드는 ‘0번 플레이어 승률’을 선공 승률로 표시했다. 이번부터 실제 선공(seed & 1)과 승자를 비교하도록 바로잡았다.

로컬 재현: 저장소 루트에서 HTTP 서버 8765, `tests/roomserver.js` 8767 실행. 테스트용 Node 패키지는 playwright와 ws. Windows는 Edge, Linux는 기존 `/opt/pw-browsers/chromium`; `BROWSER_PATH`로 변경 가능. 프로덕션 게임에는 npm 패키지를 넣지 않는다. localhost의 실제 방 서버 접근은 CORS로 제한된다. 테스트용 브라우저는 `localStorage['blackout.rtbase']='http://localhost:8767'`로 대역을 선택한다. `RT` 환경변수로 pvp 테스트 대상 변경 가능.

## 다음 단계와 미완료 범위

1. 실내 맵·캐릭터 스타일과 이동 규칙을 플레이하며 확인. 방 형태·가구는 현재 두 가지 고정 템플릿이며 선택만 무작위다.
2. 발자국이 너무 드문 문제를 사람 대전으로 평가. 전등 의존도를 낮추고 싶다면 ‘두 칸 이동 시 완전 소거’ 규칙부터 비교 실험한다. 승인 없이 가구·총성·인기척으로 새 추리 단서를 만들지 않는다.
3. 공개 대전으로 확장하기 전에 서버 심판 도입. 현재 양쪽 클라이언트는 전체 상태를 보유하므로 개발자도구 치트를 막지 못한다. 해시 비교는 보안 기능이 아니다. 숨은 전체 상태와 seed/턴 원장을 서버에 두고 각 플레이어에 허용 view와 공개 사건만 보내야 한다. 서버에서 행동 순서·AP·위치·승패·재접속을 검증한다. 서버 소스와 실제 배포 권한 확인이 선행되어야 한다.
4. GitHub 변경 검토 후 main 반영 시 Pages에 `/blackout/`이 배포되는 경로. 그 다음 실제 도메인에서 방 생성·입장·재대결·두 기기/WAN 재접속을 확인한다. 이번 로컬 검증만으로 배포 완료라고 하지 않는다.
5. 확정된 컨셉으로 홈/가구/캐릭터/발자국 개별 정지 자산 제작. 게임 전체 자산 2MB 예산 안에서 압축. 이후 힉스필드로 페인트 튐·종이 흩날림 등 필요한 모션만 제작한다.
6. 아이템(회복·가로/세로 3칸·2×2·수류탄)은 이번 변경에 포함하지 않는다. 실제 상태/해시에 추가하고 별도 밸런스·정보 노출 검사를 한다.
